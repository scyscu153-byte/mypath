## 1. 문제

명지전문대학에는 학생을 위한 프로그램이 많습니다.
**문제는 그것들이 한곳에 있지 않다는 것입니다.**

직접 조사한 결과, 재학생이 참여할 수 있는 프로그램 **143건**이
**10개 서브도메인**에 흩어져 있었습니다. (2026-08-06 수집, 출처 URL 전부 HTTP 200 확인)

| 도메인 | 건수 | 무엇이 있는가 |
|---|---|---|
| `www.mjc.ac.kr` | 51 | 비교과·전산 자격증·AI Study+·장학 공지 |
| `cls.mjc.ac.kr` | 25 | 학과 공지판 (전교 공지 미러링) |
| `mpu.mjc.ac.kr` | 16 | SMART CARE 핵심역량 프로그램 |
| `sanhak.mjc.ac.kr` | 15 | WE-GO 현장실습·Co-op·캡스톤디자인 |
| `rise.mjc.ac.kr` | 10 | RISE사업단 마이크로디그리·전문기술 과정 |
| `inter.mjc.ac.kr` | 10 | 국제교류·글로벌 현장학습 |
| `mrcc.mjc.ac.kr` | 7 | 지역협력·리빙랩 |
| `edu.mjc.ac.kr` | 6 | 평생교육원 |
| `mjcd` · `mjcs` | 3 | 학과 사이트 |

예를 들어 이런 것들이 서로 다른 곳에 있습니다.

- **하계방학 AI 비교과 프로그램** — AI 코딩 에이전트로 기획·코딩·디버깅·배포를 32시간 실습 → `cls`
- **전산 자격증 취득 지원** — 취득 시 장학금 5만 원 + 마일리지 300점 → `www`
- **WE-GO 현장실습 학기제** — 표준 3학점 / 자율 2학점 → `sanhak`
- **WE-CAN 캡스톤디자인** — 과제당 최대 200만 원 지원 → `sanhak`
- **글로벌 현장학습** — 해외 인턴십 18학점 인정 → `inter`
- **마이크로코딩 마이크로전공** — 파이썬·웹·데이터과학·IoT 18학점 → `www`

학생이 이 사이트들을 전부 뒤지면서
**"내가 가고 싶은 회사에 필요한 게 뭐고, 그걸 학교 어디서 채울 수 있는지"** 를 파악하기는 어렵습니다.

> 수집한 143건은 `js/fallback.js` 에 들어 있습니다.
> 실시간 검색이 실패했을 때의 예비 데이터로 쓰입니다.

## 2. 해결

```
   목표 기업 입력
        │
        ▼
   ① 실시간 검색 ─ 그 기업이 요구하는 역량을 웹에서 찾는다 (출처 URL 포함)
        │
        ▼
   ② 갭 분석 ─ 내 프로필(보유 자격·기술)과 비교해 부족한 것을 찾는다
        │
        ▼
   ③ 교내 프로그램 검색 ─ 흩어진 11개 사이트에서 그 갭을 메울 것을 찾는다
        │
        ▼
   ④ 다각도 평가 ─ 4개 AI 모델이 서로 다른 관점에서 평가한다
        │
        ▼
   ⑤ 추천 + 이행 기록 ─ 이행하면 프로필에 반영되어 다음 추천이 달라진다
```

## 3. 기존 서비스와의 차이

### SMART CARE (`mpu.mjc.ac.kr`) — 학교가 운영하는 학생 역량 이력관리 시스템

SMART CARE에도 프로그램 추천 기능이 있습니다. 다만 **방향이 반대입니다.**

```
SMART CARE :  나  →  (성향·기질 진단)  →  나에게 맞는 것을 찾아줌
CareerBridge :  목표 →  (요구 역량)    →  내가 맞춰야 할 것을 알려줌
```

| 구분 | SMART CARE | CareerBridge MJC |
|---|---|---|
| 추천 방향 | 나에게 맞는 것 (MBTI·TCI·CST 등 성향 진단 기반) | **목표가 요구하는 것** (채용공고 기반) |
| 역량 체계 | 학교가 정한 9개 핵심역량 (소프트스킬) | **기업이 요구하는 실제 기술** |
| 데이터 범위 | 시스템에 등록된 50건 | **11개 서브도메인에 흩어진 프로그램** |
| 갱신 방식 | 담당자 수동 등록 | **실시간 웹 검색 + 출처 URL** |

> SMART CARE를 대체하려는 것이 아닙니다.
> SMART CARE는 "나를 아는 것"을 돕고, CareerBridge MJC는 "목표에 도달하는 법"을 돕습니다.

## 4. 설계 원칙

### 원칙 1 — 자격을 판정하지 않는다

```
❌ "당신은 이 프로그램에 참여할 수 있습니다"
✅ "이런 프로그램이 있습니다. 자격은 여기서 확인하세요"
```

신청 자격, 학년 제한, 중복 참여 제한, 마감일은 학칙이나 내부 규정에 있어
웹에서 확인되지 않는 경우가 많습니다.
**AI가 "된다"고 단정하면 학생이 헛걸음합니다.**

| 규칙 | 구현 |
|---|---|
| 출처가 없으면 표시하지 않는다 | `mjc.ac.kr` 출처가 없는 항목은 결과에서 제외 |
| 자격을 판정하지 않는다 | "참여 가능" 대신 "해당될 수 있음 — 확인 필요" |
| 확인 링크를 반드시 붙인다 | 모든 결과 카드에 원문 URL |
| 게시일을 표시한다 | 오래된 정보를 사용자가 구분할 수 있게 |

### 원칙 2 — 명지대학교와 명지전문대학을 코드로 분리한다

검색 결과에 **명지대학교(`mju.ac.kr`)** 정보가 섞여 들어옵니다.
프롬프트로 "명지대학교는 제외하라"고 명시해도 발생합니다.

측정 결과:

| 검색 질의 | `mjc.ac.kr` 출처 | `mju.ac.kr` 오염 |
|---|---|---|
| 프로그래밍·개발 프로그램 | 11 | **8** |
| 현장실습·인턴십 | 11 | 5 |
| 자격증 지원 | 11 | 2 |
| AI·데이터 | 16 | 0 |

**프롬프트 지시에 의존하지 않고, 응답의 출처 도메인을 코드에서 필터링합니다.**

## 5. 기술 구성

- **프론트엔드**: Vanilla HTML/CSS/JS (빌드 도구 없음) + Tailwind CDN
- **AI**: 명지전문대학 팩트챗 게이트웨이 (OpenAI 호환 API)
- **저장**: 브라우저 localStorage (개인 데이터가 외부에 저장되지 않음)
- **배포**: Vercel (정적 파일 + Serverless Function)

### 🔐 사용자의 API 키는 저희 서버를 지나가지 않습니다

```
본인 키를 입력한 경우
   브라우저 ─────────────────────────────▶ 게이트웨이
   (localStorage 의 키로 직접 호출. 저희 서버를 거치지 않음)

키 없이 데모 모드로 쓰는 경우
   브라우저 ──▶ api/gateway.js ──▶ 게이트웨이
                (서버에만 있는 데모 키 사용. 브라우저는 이 키를 볼 수 없음)
```

**어느 경로에서도 "남의 키를 볼 수 있는 위치"가 생기지 않습니다.**

- `api/gateway.js` 에는 **요청 헤더에서 키를 읽는 코드가 아예 없습니다.**
  서버는 `DEMO_API_KEY`(환경변수)만 사용합니다.
- 이 저장소는 Public 이므로 위 내용을 코드로 직접 확인하실 수 있습니다.

> 이 구조는 게이트웨이가 CORS 를 허용하기에 가능합니다 (2026-08-06 확인).

### 왜 경로를 둘로 나눴는가 — 이것이 이 서비스의 확장 방식입니다

경로가 두 개인 것은 보안 때문만이 아닙니다. **비용 구조 때문입니다.**

명지전문대학 재학생은 누구나 팩트챗에서 자기 API 키를 발급받을 수 있고,
**1인당 월 10,000 크레딧**이 배정됩니다. 이 도구는 1회 분석에 약 **68 크레딧**을 씁니다.

```
       사용자 1명이 늘면                무엇이 늘어나는가
─────────────────────────────────────────────────────────
 일반적인 AI 서비스   운영자의 API 비용이 늘어난다
 CareerBridge MJC   그 학생 몫의 크레딧이 쓰인다 (운영자 비용 0)
```

즉 **사람이 늘어도 저희가 비용을 부담하지 않습니다.** 각자 이미 배정받은 몫을 씁니다.
학교 입장에서도 새로운 예산이 필요하지 않습니다. **이미 나눠준 크레딧이 쓰이는 것뿐입니다.**

그렇다면 데모 키는 왜 두는가 —

> **"키부터 발급받으세요"라고 하면 대부분 거기서 떠납니다.**
> 그래서 처음 온 사람은 아무 설정 없이 바로 눌러볼 수 있게 하고,
> 계속 쓸 사람만 자기 키를 넣도록 했습니다. 데모 키는 **진입로**입니다.

| | 데모 모드 | 본인 키 |
|---|---|---|
| 설정 | 없음 — URL만 열면 됨 | 1회 발급 (`mjc.factchat.bot` → API Gateway) |
| 크레딧 출처 | 저희 키 | 본인에게 배정된 월 10,000 |
| 사용량 제한 | IP당 25회/10분, 전체 180회/시간 | 없음 |
| 키가 지나는 경로 | 브라우저는 키를 보지 못함 | 저희 서버를 지나지 않음 |

앱 헤더의 **"데모 모드 · 내 키 쓰기"** 버튼에 발급 경로와 배정량을 안내해 두었고,
데모 한도에 걸리면 그 화면이 자동으로 열립니다.
**막다른 길을 만들지 않는 것**이 이 설계의 목적입니다.

#### 데모 키를 보호하는 장치 (`api/gateway.js`)

이 저장소가 Public 이므로 `/api/gateway` 주소도 공개입니다. 그래서 프록시에 제한을 걸었습니다.

| 장치 | 값 | 이유 |
|---|---|---|
| 모델 화이트리스트 | 6종만 허용 | `claude-opus-5`(1회 52.94크레딧) 같은 고가 모델 호출 차단 |
| 응답 길이 상한 | 4,000 토큰 | 크레딧 폭주 방지 |
| IP당 사용량 | 25회 / 10분 | 파이프라인 1회 = 7호출이므로 약 3회분 |
| 전체 사용량 | 180회 / 1시간 | 약 25회 분석분 |

> ⚠️ 사용량 카운터는 서버 인스턴스 메모리에 있습니다. 인스턴스가 재활용되면 초기화됩니다.
> **완전한 차단이 아니라 남용의 비용을 올리는 속도 방지턱**입니다.
> 정확한 총량 제어에는 외부 저장소가 필요하고, 이는 대회 범위를 넘어선다고 판단했습니다.

> ⚠️ 화이트리스트는 `js/gateway.js` 의 라우팅과 **반드시 일치해야 합니다.**
> 본인 키 경로는 게이트웨이를 직접 호출하므로 이 검사를 지나지 않아,
> 목록이 어긋나도 **키 없이 들어온 사용자에게만** 오류가 납니다.
> 실제로 모델을 교체한 날 이 불일치가 발생했고, `npm run check` 로 두 파일을 대조하도록 했습니다.

### 모델 선택 — 감이 아니라 측정으로 골랐습니다

동일 작업·동일 프롬프트로 직접 측정한 값입니다. (2026-08-06)

| 모델 | 1회 크레딧 | 응답 시간 | 이 프로젝트에서의 용도 |
|---|---|---|---|
| `solar-pro2` | **0.15** | 2.2초 | 시장 트렌드 관점 (Upstage) |
| `gemini-3.5-flash-lite` | **0.33** | 1.8초 | 비용·시간 관점 (Google) |
| `gpt-5.4-nano` | 1.00 | 2.0초 | 작업 분류 |
| `gpt-5.4-mini` | 1.99 | 2.8초 | 갭 분석 · 실무 관점 (OpenAI) |
| `claude-sonnet-5` | 8.00 | 6.0초 | 학업 연계 관점 (Anthropic) |
| `sonar-pro` | 28.00 | 20초 | 실시간 웹 검색 (호출 최소화) |
| `claude-opus-5` | **52.94** | 25.9초 | **사용하지 않음** |

**1회 실행 실측: 68.5 크레딧 / 7회 호출 / 12~20초.**
같은 작업을 전부 `claude-opus-5` 로 처리하면 **370.6 크레딧** — **약 5.4배**입니다.
월 10,000 크레딧 기준으로 **146회 vs 27회**입니다.

#### 측정하지 않았다면 몰랐을 것 두 가지

**① 비싼 모델이 더 나은 것이 아니었습니다.**

`gemini-3.5-flash` 는 답을 쓰기 전에 **속으로 1,187 토큰을 생각합니다.**
이 토큰도 과금되고 `max_tokens` 한도에도 포함되어, 출력이 문장 중간에서 잘렸습니다.
**즉 4개 관점 중 하나가 통째로 실패하고 있었는데 겉으로는 드러나지 않았습니다.**
숨은 추론이 없는 `flash-lite` 로 바꾸니 **4배 빠르고 24배 저렴**해졌고, 결과 품질 차이는 없었습니다.

**② 더 최신 모델이 더 나은 것도 아니었습니다.**

`solar-pro3` 에 프로그램 10개를 주면 **1번 하나만 평가하고 응답을 끝냈습니다** (전체 86자).
구버전인 `solar-pro2` 는 10개 전부를 2회 연속으로 정확히 평가했습니다.
**기준은 버전이 아니라 작업 적합성이었습니다.**

후보 6종을 각 2회씩 측정한 결과입니다.

| 후보 | 10개 중 응답 | 시간 | 숨은 추론 | 판정 |
|---|---|---|---|---|
| `solar-pro2` | 10 / 10 | 2.2초 | 0 | **채택** |
| `google/gemma-4-31B-it` | 10 / 10 | 8.7초 | 0 | 느림 |
| `grok-4-1-fast` | 10 / 10 | 10.8초 | 840 | 느림 + 토큰 낭비 |
| `seed-2-0-lite` | 10 / 10 | 14.2초 | 0 | 느림 |
| `kimi-k2.6` | 불안정 | 59초 | 0 | 탈락 |
| `LGAI-EXAONE` | 형식 실패 | 40~48초 | 0 | 탈락 |

> 결과적으로 4개 관점이 **OpenAI · Anthropic · Google · Upstage** 네 회사로 나뉩니다.
> 같은 모델에 역할 이름만 다르게 붙이면 관점이 갈리지 않기 때문입니다.
> 그래서 화면의 평가 카드마다 **어떤 모델이 매긴 점수인지 모델명을 함께 표시**합니다.
> "AI 4개를 사용합니다"를 **확인 가능한 주장**으로 만들기 위해서입니다.

## 6. 실행 방법

### 그냥 써보기

배포된 주소를 열면 됩니다. 설치는 필요 없습니다.
데모 모드로 바로 동작합니다 (사용량 제한 있음).

> **단, 심사 기간에만 열려 있습니다.** 데모 키는 팀원 개인 키이고 심사 후 내립니다.
> 그 뒤에는 아래 “내 키로 쓰기”가 정상 경로입니다.

### 내 키로 쓰기 — 재학생의 정상 경로

앱 상단의 **"내 계정으로 이용하기"** 버튼을 누르면 발급 경로가 안내됩니다.

> 명지전문대학 팩트챗(`mjc.factchat.bot`) → 좌측 하단 **API Gateway** 메뉴
> 재학생은 월 10,000 크레딧이 배정됩니다. 이 도구는 1회 분석에 약 68 크레딧을 씁니다.

입력한 키는 **이 브라우저에만 저장되고, 게이트웨이로 직접 전송됩니다.** 저희 서버를 거치지 않습니다.

### 직접 실행하기

빌드 도구가 없어 정적 파일만 열어도 화면은 동작합니다.
다만 데모 모드(Serverless Function)까지 확인하려면 Vercel CLI가 필요합니다.

```bash
git clone https://github.com/scyscu153-byte/mypath.git
cd mypath

# 데모 모드를 로컬에서 쓰려면 (본인 키를 앱에 직접 입력할 거라면 생략 가능)
cp .env.example .env.local
#   .env.local 을 열어 DEMO_API_KEY 에 본인의 팩트챗 키를 입력하세요

npx vercel dev          # http://localhost:3000
```

정적 파일만 확인하려면 아무 정적 서버나 됩니다 (`file://` 은 ES 모듈 때문에 안 됩니다).

```bash
python -m http.server 8000
```

**개발용 도구**

```bash
npm run check            # 라우팅 모델과 프록시 허용 목록이 일치하는지 검사
open dev-test.html       # UI 없이 4단계 로직만 실행해 결과·비용·커버리지 확인
open index.html?mock=1   # 크레딧을 쓰지 않고 화면만 확인
```

> ⚠️ **API 키는 절대 저장소에 커밋하지 마세요.**
> `.gitignore` 가 `.env*` 와 `.vercel` 을 제외합니다.
> 배포 환경의 키는 Vercel 환경변수(`DEMO_API_KEY`)에만 있고 저장소에는 없습니다.
> 브라우저로도 전달되지 않습니다 — `api/gateway.js` 가 서버에서만 사용합니다.

### 작업 방식 — 데이터 계약 우선, mock 기반 병렬 개발

AI 파이프라인(요구역량 검색 → 갭 분석 → 프로그램 검색 → 4모델 평가)은 순차 의존이라 한 사람이 이어서 구현합니다. 대신 결과물의 데이터 모양(`Profile`/`Target`/`ProgramMatch`, `js/types.js`)을 먼저 고정해두고, 프론트엔드는 이 모양과 똑같은 가짜 데이터로 화면을 먼저 완성한 뒤 실제 로직으로 교체하는 방식으로 병렬 진행했습니다.

```
index.html      뼈대 (초기 합의 후 고정)
js/types.js      데이터 계약 (공용)
js/ui.js          화면 · 렌더링 (유초윤)
js/pipeline.js    AI 파이프라인 (신찬영)
api/gateway.js    게이트웨이 프록시, API 키 보관 (신찬영)
```
